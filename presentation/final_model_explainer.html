2 · Step by step

  1. Build features from raw files, using only seasons up to 2013-14 (the audit found 0 rows after the cutoff). One row per account-season; conflicting values in a season become "multiple".
  2. Feature set A (reference): inside each training fold, drop features over 50% missing, rank by mutual information, remove near-duplicates (|Spearman| ≥ 0.95), keep the top 25 by random-forest importance (the two account-ID features are always kept), then drop ticket, interaction and 3 of 4 distance features. That leaves 18 in the final fit.
  3. Reference ensemble: fit an L2 logistic regression and a random forest on set A. Convert each one's scores to ranks and average them.
  4. Feature set B (add-on): 21 fixed features, with 5 continuous ones bent by piecewise-linear splines (seasons since last subscription, seasons since any purchase, 2013 donations, lifetime donations, years since first gift). This lets a straight-line model capture effects like "recency matters a lot up to ~5 seasons, then flattens".
  5. Add-on model: L2 logistic regression on set B.
  6. Combine: final = (1 − w) × reference + w × add-on. A pre-set rule picks w ∈ {0, 0.25, 0.5} and C ∈ {0.1, 1, 10, 74} using the inner folds. The add-on is used only if it beats the reference by ≥ 0.0005; among near-ties it takes the smallest weight, then the smallest C. On the full data it picked w = 0.5, C = 1.
  7. Refit on all 6,941 training accounts and predict the 2,975 test accounts.

Why the averaging helps here: logistic regression and the forest make different mistakes (their test-set rank correlation is about 0.77), so averaging them cancels some errors. That's the lecture's "close to independent" condition (s20). When the MLP was added, its errors were too similar to the others', and it added nothing.

4 · How good is it, and is it overfit?

Lockbox and public sets are different samples. With only 66 and roughly 40–60 subscribers respectively, differences under about 0.01 are noise.

  • Nested CV: choices were made inside inner folds and scored on outer folds, so the CV number is close to honest. The CV-to-public drop was only −0.004, versus −0.007 on average for your earlier tune-once models.
  • Lockbox: scored once, never seen during design. It landed above CV, the opposite of what overfitting does.
  • The model leans on the account-ID batch and donation snapshot: removing them costs −0.010. This is the main risk to discuss in your write-up.
